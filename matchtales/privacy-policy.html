5. Firebase services

Google Analytics for Firebase receives gameplay and app-interaction events, app-instance identifiers and associated device and regional information to measure use and improve the game. The reviewed code explicitly enables Analytics at device startup, independently of the ad-consent sequence. An ad-consent prompt does not by itself establish consent for all Analytics processing. Firebase Remote Config retrieves game settings, including difficulty and economy parameters. Bundled defaults are available when a remote fetch fails. Remote settings are not a cloud backup of your saved progress. See Firebase privacy and security information for service-specific processing.

9. Local saves, backups and notifications

The reviewed game saves progress, virtual balances, settings, event state and processed transaction records locally using Unity PlayerPrefs. It also keeps a local verified progress checkpoint and local advertising diagnostic logs. No publisher login or publisher cloud-save service was identified. Operating-system backups may preserve or restore app data independently; cross-device or cross-platform progress transfer is not guaranteed.

The inspected notification integration schedules reminders locally for features such as lives and rewards, subject to device permissions. It does not establish a remote push-token service. Notification preferences and permission state may be stored locally and permission-related events can be logged to Analytics. You can manage notifications in your device's settings.

10. Device-clock verification

The inspected clock guard can send an HTTPS HEAD request to https://www.google.com/generate_204 to read the response Date header when online. Google receives connection data such as your IP address and normal request metadata. The code does not attach your game save to this time request. This is separate from Analytics, advertising and purchases.

The game records device-time checks and a verified checkpoint locally. A clock inconsistency can restore an earlier checkpoint, changing progress or rewards; settings and transaction records are carried over by the inspected rollback code. This is not a guarantee that every purchased balance will be correctly preserved under every failure. Keep automatic date and time enabled and contact Support about unexpected changes. Requests can occur across launches or resumes; the policy does not promise only one lifetime request.
